1. STRATEGIE

3. FACADE

Fichier : Kernel/Runtime/NKCanvas/src/NKCanvas/Renderer/Core/NkIRenderer2D.h
Ligne 46 :

Cette interface propose des opérations simples pour utiliser le moteur de rendu 2D, comme Begin(), Draw() et End(). Elle masque une partie des différences entre les différents backends graphiques. Il s'agit d'un exemple d'abstraction simplificatrice proche du motif Façade.

5. OBSERVATEUR

Fichier : Kernel/Runtime/NKEvent/src/NKEvent/NkEventSystem.h

Les fonctions de rappel permettent à plusieurs abonnés de recevoir une notification lorsqu'un événement est distribué. C'est le principe du motif Observateur.

6. SINGLETON

Fichier : Kernel/System/NKLogger/src/NKLogger/NkLog.h
Ligne 143 :
static NkLog& Instance();

Fichier : Kernel/System/NKLogger/src/NKLogger/NkLog.cpp
Lignes 412 à 416 :
NkLog &NkLog::Instance() {
    // Meyer's singleton : static local, thread-safe en C++11+
    // L'instance est créée au premier appel, détruite à la fin du programme
    static NkLog instance;
    return instance;
}

La méthode Instance() donne un accès global à une instance unique de NkLog. La variable statique locale garantit qu'une seule instance est créée.

8. COMPOSITE

Fichier : Kernel/Runtime/NKCanvas/src/NKCanvas/Renderer/Core/NkRenderStates.h
Ligne 8 : commentaire expliquant la composition parent-enfant.
Ligne 16 :
states.transform = parentTransform;

Fichier : Kernel/Runtime/NKCanvas/src/NKCanvas/Renderer/Resources/NkSprite.cpp
Lignes 67 à 70 : commentaire décrivant l'ancien problème.
Ligne 73 : nouvelle méthode Draw() recevant les états.
Lignes 78 à 80 :
NkRenderStates s = states;
s.transform *= GetTransform();
s.texture = mTexture;

La transformation du parent est transmise à l'enfant et composée avec sa transformation locale. L'ancien code du sprite ignorait l'état reçu, ce qui empêchait son utilisation correcte comme enfant d'un objet transformé. Ce problème a été corrigé.

9. COMMANDE

Statut : motif non identifié dans les fichiers NKCanvas examinés.

La recherche des éléments suivants n'a donné aucun résultat :
- class NkCommand
- struct NkCommand
- Command::
- Undo()
- Redo()
- Replay()

Mécanisme le plus proche : le système d'événements NkEventSystem.

Différence : un événement sert à notifier les abonnés qu'une action ou un événement s'est produit. Il ne représente pas nécessairement une commande encapsulée dans un objet que l'on peut stocker, rejouer ou annuler.

CONCLUSION

Huit motifs ont été identifiés ou rapprochés de leur définition dans le code examiné. Le motif Commande n'a pas été retrouvé dans les fichiers NKCanvas recherchés. Le cas de la Façade est à considérer avec nuance, car NkIRenderer2D est avant tout une interface abstraite commune aux différents backends.
